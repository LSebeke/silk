# Silk 1.1 spec (delta)

Changes against the [v1 spec](v1.md). What is not named here stays as v1 says. Planning map: [Map: Silk 1.x roadmap](https://github.com/LSebeke/silk/issues/62).

- **Vocabulary**: [`GLOSSARY.md`](../../GLOSSARY.md).
- **Release**: minor. No Canon `formatVersion` change. One load-time migration (§C.3).
- **Feedback round** (v1.1 testing, issues #86–#101): §B amended, §E–§H added.

---

## A. Canvas gestures

Source: [Canvas: right-drag to create connected cards, drop Connection Points](https://github.com/LSebeke/silk/issues/71).

Replaces the Connection Point parts of v1 §10.2 and §10.3 (Mouse).

- **Connection Points are removed.** Edges float: they attach on the side of a Node that faces the other Node.
- **Left-drag** on a Node moves it. **Right-drag never pans**; panning stays on left/middle drag of the canvas.
- **Right-click** is decided by where the press starts and where it ends:

  | Starts on | Ends on | Result |
  |---|---|---|
  | Node A | Node A | Node context menu (as v1) |
  | Node A | Node B | Connection A → B; its editor opens on the label |
  | Node A | canvas | Creation Pipeline at the drop point, new element connected A → new |
  | canvas | canvas | Creation Pipeline, standalone Node (as v1 right-click) |
  | canvas | Node B | Creation Pipeline at the press point, new element connected new → B |
  | Connection edge | anywhere | edge context menu (as v1) |
- **While dragging**: a rubber-band line from the start point; a Node under the cursor highlights as the connect target (as the palette drop).
- **Direction**: default outgoing (from the start of the drag). Modifiers at release pick another, the same as the digit keys (v1 §10.3): Shift = incoming, Ctrl = mutual, Alt = free-form outgoing. Afterwards, `Tab` in the Connection editor cycles direction (as v1).

## B. Creation Pipeline

Replaces the pipeline steps in v1 §10.3.

1. Class box (searchable, at the spot). Digit keys skip it.
2. **Source Step**, only for classes that have one.
3. Name field, focused.
4. If created from or onto a Node: the Connection editor, focused on its label.

### B.1 Source Step
- **Classes**:

  | Class | Compendium | Generator | Blank |
  |---|---|---|---|
  | Person | ✓ | NSC Zucht (§B.3) | ✓ |
  | Creature | ✓ | – | ✓ |
  | Location | ✓ Scene → Overview Scene (§B.2.1) | – | ✓ no Scene |
  | Event | ✓ Scene → Event Scene (§B.2.1) | later: Event setup assistant (out of scope for 1.1) | ✓ Preset Scene (v1) |
  | others | no Source Step | | |
- **Widget**: a compass of four buttons at the spot. Mouse and arrow keys work the same:

  | Key | Choice |
  |---|---|
  | `↑` | Compendium (§B.2) |
  | `←` | Generator |
  | `→` | Blank |
  | `↓` / `Esc` | Cancel the creation |
- Unavailable choices are greyed with a tooltip; their arrow does nothing.
- Class box and compass run as commands (ADR 0003, §D): `pipeline.search`, `pipeline.pickClass`, `pipeline.pickSource`, `pipeline.cancel`.
- Every entry point except Adopt runs it: digit keys, class box (right-click, right-drag, Node context menu), palette, `c` "New Node". Adopt (§6 drag from sidebar/compendium) already has a doc and skips it.
- **Name step** after a source pick: prefilled with the source actor's name, all text selected.
- **Ghost worlds** (Materialize on demand): a Compendium pick stores the entry's UUID on the element and imports it when the element is Materialized. It also stores the entry's `img`, so the Ghost's card shows the portrait before Materialize. A Generator pick Materializes at once.

### B.2 Compendium picker
- A window with a search bar (focused on open, so typing starts at once) and a side list of sources.
- **Side list**: **All** (default), **World**, then each matching pack with its entry count. Single-select; it filters the results.
- **Packs listed**: Actor packs, only entries of the class's type (Person `npc`, Creature `creature`). Packs whose `flags.dsalang` differs from `game.i18n.lang` are hidden, the same rule DSA5 uses; packs without the flag are shown. Packs the user cannot see (`pack.visible` false) and packs with no entry of the class's type are hidden too.
- **World**: world actors of the matching type that are not Story Elements. Player Characters never appear.
- **Rows**: image, name, source label. Search matches the name within the current source.
- **Source label** (#88): the pack's folder ancestry, then the pack label, joined by ` › `, e.g. "Adventures › Nightblack sea › Karten" (`pack.folder` + `folder.ancestors`: module `packFolders` and user compendium folders alike). A pack without a folder is prefixed with its package title (module/system title). The side list is flat, sorted by label. Too long: the start stays visible, the end is cut with "…", the full label is the tooltip.
- **Merged rows** (#87): in **All**, entries with the same name (case-insensitive, trimmed) are one row with a "×N" badge, World actors included. A single pack or World in the side list shows its entries unmerged.
- **Choosing a source**: picking a merged row turns the window into that entry's source list: World entries first, then packs by label; each row has image, source label and a chip **Adopt** (World) or **Import** (pack). `↑`/`↓`/`Enter` pick, `Esc` goes back to the results. Picking one has that source's outcome (below).
- **Keys**: `↑`/`↓` move in the results, `Enter` picks, `Esc` goes back to the Source Step.
- **Commands** (ADR 0003, §D): search, source, pick and cancel run as `picker.search`, `picker.source`, `picker.pick`, `picker.cancel`.
- **Outcome**:
  - Pack entry: copied into the World by a normal Foundry import, then handled as a Silk-created element (Companion Journal, default Info Blocks).
  - World actor: **Adopted** (§6): the doc stays put, it gets a Companion Journal with only the Appearance block (§C.2), no other default Info Blocks.

### B.2.1 Scene picker (Location, Event)
Source: #90. The Compendium picker with Scenes instead of Actors.
- **Packs listed**: Scene packs, same visibility and `dsalang` rules. **World**: world Scenes not linked to an element.
- **Outcome**: a pack Scene is imported with its config untouched (walls, lights, grid; no Scene Preset): Location → its Overview Scene, Event → its Event Scene (versioned like any Event Scene, v1 §11.2). A World Scene is Adopted (v1 §6 Scene row) as the picked class.
- **Images**: the element's `img` (journal Cover) is the Scene's `background.src`. The card shows the Scene's own `thumb`; if it has none, Silk downsamples `background.src` once to a WebP data URL (longest side 192 px, quality 0.7) and stores it on the element record (`thumb`). Foundry's Scene thumbs are never changed.
- **Ghost worlds**: as for Actor picks, the Scene UUID and the card image are stored; the Scene is imported on Materialize.

### B.3 Generator: NSC Zucht
- **Available** when `game.modules.get('dsa5-mastersworkshop')?.active` and the user is the GM.
- **Opening**: Silk imports `modules/dsa5-mastersworkshop/modules/npcgenerator.js` and renders its default `getInstance()`. The module has no public API, so the import is guarded: if it fails, Generator is greyed with a tooltip.
- **Startup probe**: on `ready`, when the module is active and the user is the GM, Silk tries the import once without opening anything. A failure greys Generator from the start (no toast; a failure on opening also warns).
- **Binding**: the first NPC Actor the GM creates while the generator is open (`createActor` hook) is the pick; Silk closes the generator. `element.create` gets `source: { kind: 'generator', id: 'nsc-zucht', actorUuid }` and binds that Actor at once, in either Materialize mode: Silk flags it, moves it to Silk's Person folder with player ownership None, and adds the Companion Journal and default Info Blocks (Appearance flagged, §C.2). The actor's name is the element's (prefilled with the generator's, then whatever the name step sets). The generator's image, stats and items stay. Actors that are already Story Elements are never taken.
- **Actor gone** before binding (or already a Story Element): Silk Materializes a fresh Person instead, as for any Ghost.
- **Closed without generating**: back to the Source Step.

### B.4 Interaction budget
Replaces the "Create connected ≤ 2 interactions" row of v1 §14: the **fastest** path to a connected element is ≤ 2 user actions per entry point (e.g. digit + `→`; class pick + `→`; right-drag + class pick for classes without a Source Step). The name and label steps are not counted. Extra customisation (Compendium, Generator) may take more steps.

## C. Info Blocks and Appearance

Extends v1 §4 and §8 (Controls).

### C.1 Editing in Element Detail
For every class:
- **Add**: a "+ Info Block" button; the name is edited inline.
- **Rename** inline, **delete** with a confirmation.
- **Edit text** inline with Foundry's ProseMirror editor; writes through `infoBlock.edit`. Each block also has an "open in Foundry" link.
- **Reorder** by drag (page `sort`), among Info Blocks only. Cover, Connections and Player Notes pages keep their places.
- Node context menu: **Add Info Block…** opens Element Detail with a new block, its name field focused.

### C.2 Appearance
- The Appearance block is marked by the page flag `flags.silk.appearance: true`, not by its name.
- **Deleted**: the element has no Appearance to Reveal. Players see the class's default icon (§4, `icons/svg/…`) as `img`, Cover and token texture, permanently. The real image stays in `flags.silk.img`.
- **Re-added**: on an actor class without one, the "+ Info Block" control offers **Appearance** as a preset (a menu on the control). Adding it restores the hood behaviour.
- **Adopt**: an adopted Person/Creature actor gets an Appearance block (flagged), and no other default blocks. This holds for every Adopt way in (sidebar/compendium drag, context menu, bulk folder, World picks in the Compendium picker (§B.2), an inventory item's "also adopt actor"). It amends v1 §6 Adopt "Content" and "Reveal":
  - **Players can't see the actor yet**: it is hooded at Adopt. `img` and the prototype and placed token textures show the hooded image; the real ones wait in `flags.silk.img` / `flags.silk.token`. Ownership is unchanged.
  - **Players can already see it** (it counts as Revealed, v1 §6): its Appearance counts as Revealed too (the Revelation Map's `appearance` entry), so it stays unhooded.
- **Flag**: `flags.silk.appearance` is a second exception to v1 §2 "`flags.silk` holds ids only" (after `silk.img`).

### C.3 Migration
On load, a Person/Creature Info Block whose name equals the localised "Appearance" and that has no flag gets `flags.silk.appearance: true`. Done once per element: an element counts as done only once it was migrated or found to need nothing. A Materialized element whose doc or journal is not found stays pending and is tried again on the next load.

### C.4 Hooded image
- Default: Foundry core `icons/svg/mystery-man-black.svg` (replaces Silk's shipped `assets/hooded.svg`, which is removed).
- The world setting override stays (v1 §13: "Hooded default image", default now the core icon).
- **1.0 fallback**: a world that saved 1.0's default (`modules/silk/assets/hooded.svg`) or an empty value uses the core icon.

## E. Canvas cards and Focus

### E.1 Cards (#96, #97)
Replaces the full-card layout of v1 §10.2.
- Rows, top to bottom: class label (restored icon at the right); the name, wrapped (no ellipsis, no line limit, fixed card width); one control row: Status chip left, eye and Focus Pin right.
- The card's height grows to fit. Layout (Untangle, frames, camera) uses the measured size.
- At the two lower zoom levels the name wraps too, at most 3 lines.
- A card with a Scene source shows the element's `thumb` when set, else `img` (§B.2.1).

### E.2 Sticky Focus seeds (#89)
Amends v1 §10.6 "deselecting collapses it": when the selection is cleared and the active Scene gives no seeds, the last selection stays as the seeds. A new selection replaces them; an active Scene with seeds clears them. With Scene seeds, deselecting collapses to them as in v1. Sticky seeds are not persisted. Clearing the selection never moves the camera.

### E.3 Legend (#98)
- Bottom left of the World Canvas, **open by default**; a "?" button and the `?` key toggle it. Open/closed is a client setting.
- Three groups: **Keys** (canvas keys, with their condition, e.g. "on a selected Connection"), **Mouse** (gestures, incl. the right-drag table §A and modifiers), **Foundry keybindings** (Silk's, read from `game.keybindings` so rebinds show).
- Generated from the same tables the canvas uses, so it cannot drift from the code.

### E.4 Delete key (#93)
`Del`/`Backspace` with only Connections selected deletes them at once (`connection.delete`), no confirmation. With Nodes selected, the Node delete flow runs (with its confirmation) and also deletes the selected Connections.

## F. Connections

### F.1 Edge context menu (#91)
- The edge **and its label** open the edge menu on right-click; the edge's hit area is ~16 px wide.
- Entries: **Open details** (§F.2), Reveal, Edit label, **Directed ⇄ Mutual** (`connection.cycleDirection`), Cycle type, **Reverse direction** (`connection.flip`), Delete.

### F.2 Connection Detail (#92, #100)
- A window per Connection, opened by double-clicking the edge or its label, the edge menu's **Open details**, and an edit button beside each Connection in Element Detail.
- Content: both endpoints (each opens its Element Detail); the label inline (free-form only); type and direction selects and a **Reverse** button; the eye toggle; **Notes**; Delete with a confirmation.
- **Notes**: one optional rich-text field `notes` (HTML, ProseMirror) on the Connection record. GM only: never in the Player View, on Connections pages, or in Search. Merged per field like `label`. Old records read as empty; no `formatVersion` change.
- `F2` keeps editing the label inline on the canvas.

## G. Element Detail and menus

### G.1 Layout (#86, #94)
- Side padding 16 px. The header (name and its buttons) stays fixed; the body scrolls.
- A pencil button beside the name edits it inline: `Enter`/blur save (`element.rename`), `Esc` cancels.

### G.2 Sheet and journal (#95)
Replaces the Node menu's "Open sheet" (v1 §8): actor and item classes have **Open sheet** (the main doc only) and **Open journal** (the Companion Journal). Journal classes have only **Open journal** (their main doc).

### G.3 Image & token editor (#101)
- Person and Creature Element Detail has an **Image & token** button. It opens Silk's editor (not Foundry's TokenConfig, which would write over a hood):
  - **Sheet image**: Foundry FilePicker.
  - **Token image**: "Same as sheet image" (default on) or its own FilePicker.
  - **Token ring**: on/off (`ring.enabled`), ring and background colours (default empty: the world ring decides).
  - **Position**: a round preview; dragging sets the token texture offset, wheel or slider its scale (the ring subject scale while the ring is on). **Reset** restores defaults. Only the token is positioned; image files are never changed.
- Writes `actor.img`, `prototypeToken` and the placed tokens of linked actors.
- **Ring style** is the world's `core.dynamicTokenRing` (DSA5 registers `dsa5token`, `dsa5token_blank`); Silk never changes it.
- **Hooded** (§C.2): image, token image and position go to `flags.silk.img` / `flags.silk.token` and apply at Reveal; players keep seeing the hood, centred. Ring settings apply at once.
- **Ghost**: a sheet-image change is written to the record; a token, ring or position change Materializes first (toast), like `infoBlock.open`.

## H. Canon entry points (#99)
v1 §11.5 opens the Canon window "from the canvas toolbar"; 1.1 makes that concrete:
- **Canon chip** in the canvas toolbar: "<Canon name> · <main | Adventure name>", click opens the Canon window.
- **Unbound World**: the canvas shows an empty-state card "No Canon yet" with a button that opens the Canon window (create or pick).
- **Module Settings**: a menu button "Open Canon window" (`game.settings.registerMenu`), GM only.
- The scene-control button stays one button (`canvas.open`).
