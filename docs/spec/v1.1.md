# Garn 1.1 spec (delta)

Changes against the [v1 spec](v1.md). What is not named here stays as v1 says. Planning map: [Map: Garn 1.x roadmap](https://github.com/LSebeke/garn/issues/62).

- **Vocabulary**: [`GLOSSARY.md`](../../GLOSSARY.md).
- **Release**: minor. No Canon `formatVersion` change. One load-time migration (§C.3).
- **Feedback round** (v1.1 testing, issues #86–#101): §B amended, §E–§H added.
- **Feedback round 2** (issues #133–#146): §F.3, §G.3–G.5, §I added; §E.1, §F.1, §G.1 amended.
- **Feedback round 4** (issues #181, #182): §G.3 Lock rotation and hooded ring amended.
- **Feedback round 3** (issues #166–#171): §G.3 rewritten (no Garn shader, cropped subject file, draw order, size factor, all tokens follow), §G.3.1 Imported images added (amends §C.2 hood and Reveal). Second load-time migration (§G.3.2).

## A. Canvas gestures

Source: [Canvas: right-drag to create connected cards, drop Connection Points](https://github.com/LSebeke/garn/issues/71).

Replaces the Connection Point parts of v1 §10.2 and §10.3 (Mouse).

- **Connection Points are removed.** Edges float: they attach on the side of a Node that faces the other Node.
- **Left-drag** on a Node moves it. **Right-drag never pans**; panning stays on left/middle drag of the canvas.
- **Right-click** is decided by where the press starts and where it ends:

  | Starts on | Ends on | Result |
  |---|---|---|
  | Node A | Node A | Node context menu (as v1) |
  | Node A | Node B | Connection A → B; its editor opens on the label |
  | Node A | canvas | Creation Pipeline at the drop point, new element connected A → new |
  | canvas | canvas | Creation Pipeline, standalone Node (as v1 right-click) |
  | canvas | Node B | Creation Pipeline at the press point, new element connected new → B |
  | Connection edge | anywhere | edge context menu (as v1) |
- **While dragging**: a rubber-band line from the start point; a Node under the cursor highlights as the connect target (as the palette drop).
- **Direction**: default outgoing (from the start of the drag). Modifiers at release pick another, the same as the digit keys (v1 §10.3): Shift = incoming, Ctrl = mutual, Alt = free-form outgoing. Afterwards, `Tab` toggles directed ⇄ mutual and `Shift+Tab` reverses (§F.1).

## B. Creation Pipeline

Replaces the pipeline steps in v1 §10.3.

1. Class box (searchable, at the spot). Digit keys skip it.
2. **Source Step**, only for classes that have one.
3. Name field, focused.
4. If created from or onto a Node: the Connection editor, focused on its label.

### B.1 Source Step
- **Classes**:

  | Class | Compendium | Generator | Blank |
  |---|---|---|---|
  | Person | ✓ | NSC Zucht (§B.3) | ✓ |
  | Creature | ✓ | – | ✓ |
  | Location | ✓ Scene → Overview Scene (§B.2.1) | – | ✓ no Scene |
  | Event | ✓ Scene → Event Scene (§B.2.1) | later: Event setup assistant (out of scope for 1.1) | ✓ Preset Scene (v1) |
  | others | no Source Step | | |
- **Widget**: a compass of four buttons at the spot. Mouse and arrow keys work the same:

  | Key | Choice |
  |---|---|
  | `↑` | Compendium (§B.2) |
  | `←` | Generator |
  | `→` | Blank |
  | `↓` / `Esc` | Cancel the creation |
- Unavailable choices are greyed with a tooltip; their arrow does nothing.
- Class box and compass run as commands (ADR 0003, §D): `pipeline.search`, `pipeline.pickClass`, `pipeline.pickSource`, `pipeline.cancel`.
- Every entry point except Adopt runs it: digit keys, class box (right-click, right-drag, Node context menu), palette, `c` "New Node". Adopt (§6 drag from sidebar/compendium) already has a doc and skips it.
- **Name step** after a source pick: prefilled with the source actor's name, all text selected.
- **Ghost worlds** (Materialize on demand): a Compendium pick stores the entry's UUID on the element and imports it when the element is Materialized. It also stores the entry's `img`, so the Ghost's card shows the portrait before Materialize. A Generator pick Materializes at once.

### B.2 Compendium picker
- A window with a search bar (focused on open, so typing starts at once) and a side list of sources.
- **Side list**: **All** (default), **World**, then each matching pack with its entry count. Single-select; it filters the results.
- **Packs listed**: Actor packs, only entries of the class's type (Person `npc`, Creature `creature`). Packs whose `flags.dsalang` differs from `game.i18n.lang` are hidden, the same rule DSA5 uses; packs without the flag are shown. Packs the user cannot see (`pack.visible` false) and packs with no entry of the class's type are hidden too.
- **World**: world actors of the matching type that are not Story Elements. Player Characters never appear.
- **Rows**: image, name, source label. Search matches the name within the current source.
- **Source label** (#88): the pack's folder ancestry, then the pack label, joined by ` › `, e.g. "Adventures › Nightblack sea › Karten" (`pack.folder` + `folder.ancestors`: module `packFolders` and user compendium folders alike). A pack without a folder is prefixed with its package title (module/system title). The side list is flat, sorted by label. Too long: the start stays visible, the end is cut with "…", the full label is the tooltip.
- **Merged rows** (#87): in **All**, entries with the same name (case-insensitive, trimmed) are one row with a "×N" badge beside its source label (the first source's), World actors included. A single pack or World in the side list shows its entries unmerged.
- **Choosing a source**: picking a merged row turns the window into that entry's source list: World entries first, then packs by label; each row has image, source label and a chip **Adopt** (World) or **Import** (pack). `↑`/`↓`/`Enter` pick, `Esc` goes back to the results. Picking one has that source's outcome (below).
- **Keys**: `↑`/`↓` move in the results, `Enter` picks, `Esc` goes back to the Source Step.
- **Commands** (ADR 0003, §D): search, source, pick and cancel run as `picker.search`, `picker.source`, `picker.pick`, `picker.cancel`.
- **Outcome**:
  - Pack entry: copied into the World by a normal Foundry import, then handled as a Garn-created element (Companion Journal, default Info Blocks).
  - World actor: **Adopted** (§6): the doc stays put, it gets a Companion Journal with only the Appearance block (§C.2), no other default Info Blocks.

### B.2.1 Scene picker (Location, Event)
Source: #90. The Compendium picker with Scenes instead of Actors.
- **Packs listed**: Scene packs, same visibility and `dsalang` rules. **World**: world Scenes not linked to an element.
- **Outcome**: a pack Scene is imported with its config untouched (walls, lights, grid; no Scene Preset): Location → its Overview Scene, Event → its Event Scene (versioned like any Event Scene, v1 §11.2). A World Scene is Adopted (v1 §6 Scene row) as the picked class.
- **Images**: the element's `img` (journal Cover) is the Scene's `background.src`. The card shows the Scene's own `thumb`; if it has none, Garn downsamples `background.src` once to a WebP data URL (longest side 192 px, quality 0.7) and stores it on the element record (`thumb`). Foundry's Scene thumbs are never changed.
- **Ghost worlds**: as for Actor picks, the Scene UUID and the card image are stored; the Scene is imported on Materialize.

### B.3 Generator: NSC Zucht
- **Available** when `game.modules.get('dsa5-mastersworkshop')?.active` and the user is the GM.
- **Opening**: Garn imports `modules/dsa5-mastersworkshop/modules/npcgenerator.js` and renders its default `getInstance()`. The module has no public API, so the import is guarded: if it fails, Generator is greyed with a tooltip.
- **Startup probe**: on `ready`, when the module is active and the user is the GM, Garn tries the import once without opening anything. A failure greys Generator from the start (no toast; a failure on opening also warns).
- **Binding**: the first NPC Actor the GM creates while the generator is open (`createActor` hook) is the pick; Garn closes the generator. `element.create` gets `source: { kind: 'generator', id: 'nsc-zucht', actorUuid }` and binds that Actor at once, in either Materialize mode: Garn flags it, moves it to Garn's Person folder with player ownership None, and adds the Companion Journal and default Info Blocks (Appearance flagged, §C.2). The actor's name is the element's (prefilled with the generator's, then whatever the name step sets). The generator's image, stats and items stay. Actors that are already Story Elements are never taken.
- **Actor gone** before binding (or already a Story Element): Garn Materializes a fresh Person instead, as for any Ghost.
- **Closed without generating**: back to the Source Step.

### B.4 Interaction budget
Replaces the "Create connected ≤ 2 interactions" row of v1 §14: the **fastest** path to a connected element is ≤ 2 user actions per entry point (e.g. digit + `→`; class pick + `→`; right-drag + class pick for classes without a Source Step). The name and label steps are not counted. Extra customisation (Compendium, Generator) may take more steps.

## C. Info Blocks and Appearance

Extends v1 §4 and §8 (Controls).

### C.1 Editing in Element Detail
For every class:
- **Add**: a "+ Info Block" button; the name is edited inline.
- **Rename** inline, **delete** with a confirmation.
- **Edit text** inline with Foundry's ProseMirror editor; writes through `infoBlock.edit`. Each block also has an "open in Foundry" link.
- **Reorder** by drag (page `sort`), among Info Blocks only. Cover, Connections and Player Notes pages keep their places.
- Node context menu: **Add Info Block…** opens Element Detail with a new block, its name field focused.

### C.2 Appearance
- The Appearance block is marked by the page flag `flags.garn.appearance: true`, not by its name.
- **Deleted**: the element has no Appearance to Reveal. Players see the class's default icon (§4, `icons/svg/…`) as `img`, Cover and token texture, permanently. The real image stays in `flags.garn.img`.
- **Re-added**: on an actor class without one, the "+ Info Block" control offers **Appearance** as a preset (a menu on the control). Adding it restores the hood behaviour.
- **Adopt**: an adopted Person/Creature actor gets an Appearance block (flagged), and no other default blocks. This holds for every Adopt way in (sidebar/compendium drag, context menu, bulk folder, World picks in the Compendium picker (§B.2), an inventory item's "also adopt actor"). It amends v1 §6 Adopt "Content" and "Reveal":
  - **Players can't see the actor yet**: it is hooded at Adopt. `img` and the prototype and placed token textures show the hooded image; the real ones wait in `flags.garn.img` / `flags.garn.token`. Ownership is unchanged.
  - **Players can already see it** (it counts as Revealed, v1 §6): its Appearance counts as Revealed too (the Revelation Map's `appearance` entry), so it stays unhooded.
- **Flag**: `flags.garn.appearance` is a second exception to v1 §2 "`flags.garn` holds ids only" (after `garn.img`).

### C.3 Migration
On load, a Person/Creature Info Block whose name equals the localised "Appearance" and that has no flag gets `flags.garn.appearance: true`. Done once per element: an element counts as done only once it was migrated or found to need nothing. A Materialized element whose doc or journal is not found stays pending and is tried again on the next load.

### C.4 Hooded image
- Default: Foundry core `icons/svg/mystery-man-black.svg` (replaces Garn's shipped `assets/hooded.svg`, which is removed).
- The world setting override stays (v1 §13: "Hooded default image", default now the core icon).
- **1.0 fallback**: a world that saved 1.0's default (`modules/garn/assets/hooded.svg`) or an empty value uses the core icon.

## E. Canvas cards and Focus

### E.1 Cards (#96, #97)
Replaces the full-card layout of v1 §10.2.
- Rows, top to bottom: class label (restored icon at the right); the name, wrapped (no ellipsis, no line limit, fixed card width); one control row: Status chip left, eye and Focus Pin right.
- The card's height grows to fit. Layout (Untangle, frames, camera) uses the measured size.
- At the two lower zoom levels the name wraps too, at most 3 lines.
- A card with a Scene source shows the element's `thumb` when set, else `img` (§B.2.1).

### E.2 Sticky Focus seeds (#89)
Amends v1 §10.6 "deselecting collapses it": when the selection is cleared and the active Scene gives no seeds, the last selection stays as the seeds. A new selection replaces them; an active Scene with seeds clears them. With Scene seeds, deselecting collapses to them as in v1. Sticky seeds are not persisted. Clearing the selection never moves the camera.

### E.3 Legend (#98)
- Bottom left of the World Canvas, **open by default**; a "?" button and the `?` key toggle it. Open/closed is a client setting.
- Three groups: **Keys** (canvas keys, with their condition, e.g. "on a selected Connection"), **Mouse** (gestures, incl. the right-drag table §A and modifiers), **Foundry keybindings** (Garn's, read from `game.keybindings` so rebinds show).
- Generated from the same tables the canvas uses, so it cannot drift from the code. **Mouse** covers every pointer gesture: left-drag move, pan, double-click (Element / Connection Detail), right-click on an edge or label, and the right-drag table.
- The panel lets the pointer through to the canvas; only its "?" button takes clicks.

### E.4 Delete key (#93)
`Del`/`Backspace` with only Connections selected deletes them at once (`connection.delete`), no confirmation. With Nodes selected, the Node delete flow runs (with its confirmation) and also deletes the selected Connections; declining the confirmation deletes nothing.

## F. Connections

### F.1 Edge context menu (#91)
- The edge **and its label** open the edge menu on right-click; the edge's hit area is ~16 px wide.
- `Esc` closes an open menu only, never the canvas window.
- Entries: **Open details** (§F.2), Reveal, Edit label, **Directed ⇄ Mutual** (`connection.toggleDirection`; never reverses), Cycle type, **Reverse direction** (`connection.flip`), Delete.
- **Keys** (amends v1 §10.3 `Tab`): on a selected Connection `Tab` toggles directed ⇄ mutual, `Shift+Tab` reverses it. `connection.cycleDirection` is removed.
- **Pointer targets** (#138): one classifier tells Node, edge, edge label and empty canvas apart for right-press, context menu and double-click. A right-press on an edge or its label never starts the Creation Pipeline (§A row "Connection edge").

### F.2 Connection Detail (#92, #100)
- A window per Connection, opened by double-clicking the edge or its label, the edge menu's **Open details**, and an edit button beside each Connection in Element Detail.
- Content: both endpoints (each opens its Element Detail); the label inline (free-form only); type and direction selects and a **Reverse** button; the eye toggle; **Notes**; Delete with a confirmation.
- **Notes**: one optional rich-text field `notes` (HTML, ProseMirror) on the Connection record. GM only: never in the Player View, on Connections pages, or in Search. Merged per field like `label`. Old records read as empty; no `formatVersion` change.
- `F2` keeps editing the label inline on the canvas.

### F.3 Default Connection (#141)
Extends v1 §5 "create from" defaults to every new Connection (right-drag Node → Node, `c`, palette drop, `connection.create` without `type`):
- If exactly one behavioural type is valid between the two classes, in either direction, it is the default; if only the reverse is valid, the endpoints are swapped (drag Item → Person = Person owns Item). None or several: free-form.
- Only the no-modifier default may swap. An explicit direction (Shift, a picked direction) stays as asked; with no behavioural type valid that way it is free-form.
- Alt forces free-form. Ctrl (mutual) is always free-form: behavioural types are directed.
- A new element gets the same Connection whatever the gesture (palette, digit keys, right-drag Node → canvas or canvas → Node): v1 §5, e.g. a new Location sits inside its origin.

## G. Element Detail and menus

### G.1 Layout (#86, #94)
- Side padding 16 px. The header (name and its buttons) stays fixed; the body scrolls.
- A pencil button beside the name edits it inline: `Enter`/blur save (`element.rename`), `Esc` cancels.
- **No nested scrolling** (#143), for every Garn window: only the window body scrolls. Rich-text editors (Info Blocks, Connection Notes) grow with their content. A list in a window whose body does not scroll (picker results, side list) may scroll.
- **Rich text** (#142): Info Blocks and Connection Notes show read-only with an always-visible pencil that switches to the editor.

### G.2 Sheet and journal (#95)
Replaces the Node menu's "Open sheet" (v1 §8): actor and item classes have **Open sheet** (the main doc only) and **Open journal** (the Companion Journal). Journal classes have only **Open journal** (their main doc).

### G.3 Image & token editor (#101)
- Person and Creature Element Detail has an **Image & token** button. It opens Garn's editor (not Foundry's TokenConfig, which would write over a hood):
  - **Sheet image**: Foundry FilePicker.
  - **Token image**: "Same as sheet image" (default on) or its own FilePicker.
  - **Token ring**: on/off (`ring.enabled`), ring and background colours (default empty: the world ring decides).
  - **Lock rotation** (#136): `lockRotation` on the prototype and placed tokens. Not hooded. It writes only `lockRotation`: never a look edit, no subject file, an imported actor keeps its original look (#181).
  - **Position**: dragging pans, wheel or slider zooms, **0.5 to 8**, step 0.05 (#137, #167). Above 1 the image always fills the ring (drag is clamped); below 1 it may sit anywhere inside the ring, the background colour fills the rest. **Reset** restores defaults. The source image files are never changed.
  - **Draw order** (#170): **Ring in front** (default) or **Illustration in front**, per actor. Background is always behind. Stored as `flags.garn.order` (only for `illustration`; a seventh exception to v1 §2).
  - **Preview** (#135): the same cropped subject Garn writes (below), over the background colour and with the world's ring frame (the `core.dynamicTokenRing` style from `CONFIG.Token.ring`, e.g. DSA5's spritesheet), drawn at the actor's size factor in its grid square. Without the ring: the plain token.
- **Ring composition** (#134, #171): Garn ships no shader; Foundry draws background, ring, then subject. With the ring on, Garn renders the subject itself: the image, posed (pan and zoom baked in) and cropped to a circle, as a WebP file. The crop is the ring's inner edge for Ring in front, its outer edge for Illustration in front. The file goes to `ring.subject.texture`; `texture.src` keeps the uncropped image. `ring.subject.scale` stays 1. One pure geometry function (core Portrait) gives the crop for both the file and the preview. Without the ring: `texture.src` with the pose as `texture.anchorX/Y`, `texture.fit`, and no file.
  - **Files**: `Data/garn/<worldId>/tokens/<actorId>-<hash>.webp`, named by content (no stale caches), uploaded by the GM (`FilePicker.implementation.upload`). Replaced files are left behind (Foundry has no delete).
  - **`flags.garn.subject`** records the source image, pose and ring edges the file was made from (a sixth exception to v1 §2); a file is rebuilt only when one of them changes. `flags.garn.pose` holds the real pose whenever it is not centred, hooded or not.
  - **Rebuilt** on every editor commit, and on GM load when the world ring style (its inner/outer edge, stored with each file) changed; then the tokens are rewritten.
- **Size factor** (#168): `texture.scale` is the actor's size factor (DSA5: tiny 0.5, small 0.8, set at token creation), never written by Garn. Ring, background and subject shrink or grow together, natively.
- **All tokens follow** (#166): every write goes to `actor.img`, `prototypeToken` and every placed token of the actor (linked and unlinked, all Scenes), also for a sheet-image-only edit when the token is "Same as sheet image", and on the merge path. Hand edits to single placed tokens are overwritten.
- **Ring style** is the world's `core.dynamicTokenRing` (DSA5 registers `dsa5token`, `dsa5token_blank`); Garn never changes it.
- **Hooded** (§C.2): image, token image and position go to `flags.garn.img` / `flags.garn.token` / `flags.garn.pose` (anchor + scale; a third exception to v1 §2 "ids only", §C.2) and apply at Reveal; players keep seeing the hood, always with the ring on (world ring style, default colours) and centred at 0.7 of the subject (#133, #182). The hood goes through the same subject crop and draw order (its own file). Ring settings (on/off, colours) belong to the real look and wait in `flags.garn.ring` (a ninth exception to v1 §2) until Reveal; Lock rotation applies at once. `flags.garn.hood` (the hood image in use) is a fourth exception to v1 §2.
- **Ghost**: a sheet-image change is written to the record; a token, ring or position change Materializes first (toast), like `infoBlock.open`.

### G.3.1 Imported images (#169)
- **Imported**: an actor that came in by Adopt, a Compendium pick or NSC Zucht. At import Garn stores its `img`, `prototypeToken.texture` and `ring` in `flags.garn.original` (a fifth exception to v1 §2); NSC Zucht actors have no compendium source, so the flag is the only copy.
- Garn never changes an imported actor's look on its own: only an editor commit does.
- **Hood**: an unrevealed imported actor still shows the hood (§C.2). Showing the hood stores everything it overwrites (`img`, texture src, fit, anchor, scale, `ring.subject`); Reveal restores all of it exactly. This holds for every hooded actor. Stored in `flags.garn.unhooded` (an eighth exception to v1 §2); a token edit while hooded drops it, so Reveal applies Garn's look instead.
- **Restore imported images**: an editor button, shown when `flags.garn.original` exists. Writes the originals back to `img`, the prototype and every placed token and clears Garn's look (pose, draw order, subject file). On a hooded actor the originals become the real look; the hood stays until Reveal.

### G.3.2 Migration (round 3)
On the first GM load: for actors with a Garn look written by 1.1 round 2, Garn builds the subject files, sets `texture.scale` back to the size factor of the actor's size category and `ring.subject.scale` to 1. Imported actors without a Garn look are left alone.

### G.4 Appearance image (#144)
- The Appearance page starts with a Garn-managed image region (`<figure data-garn-portrait>`) showing the element's **real** image (sheet image). Garn rewrites it when the real image changes and restores it on load if it is missing.
- Players get the page only with the Appearance Reveal, so the real image never shows early.
- Element Detail shows the region read-only above the block's text; the editor edits only the text.

### G.5 Player canvas cards (#145)
Player canvas cards wrap names like §E.1 (one shared card-name component).

## H. Canon entry points (#99)
v1 §11.5 opens the Canon window "from the canvas toolbar"; 1.1 makes that concrete:
- **Canon chip** in the canvas toolbar: "<Canon name> · <main | Adventure name>", click opens the Canon window.
- **Unbound World**: the canvas shows an empty-state card "No Canon yet" with a button that opens the Canon window (create or pick).
- **Module Settings**: a menu button "Open Canon window" (`game.settings.registerMenu`), GM only.
- The scene-control button stays one button (`canvas.open`).

## I. Token Box (#140)
Amends v1 §5 **present at** ("in the box for Narrative, stacked at an edge for Battle/Travel") and v1 §7.
- **Every Event Scene** has a Token Box: Preset Scenes, Scenes from the Scene picker (§B.2.1) and Adopted Scenes. Tokens of **present at** actors are placed hidden in it, in a grid.
- **Look**: a Drawing, white fill, black outline, label "Tokens" (localised), `flags.garn.box: true`.
- **Place**: in the Scene padding, never over the background image: just outside the map's top-left corner, a grid square away. It grows with its tokens. Without room (padding too small), Garn raises the Scene's `padding` just enough, up to 0.5 (the one config change on an imported Scene); beyond that it keeps adding rows along the top edge. Tokens are never stacked.
- A box the GM moved or resized keeps its place; Garn places into it. When it is full, Garn adds a row above it (its bottom-right corner stays).
- **Preset stored**: `flags.garn.preset` (`travel` / `battle` / `narrative` / `overview` / `none`). Imported and Adopted Scenes: `none`. **Migration** on load: a Scene without the flag gets `narrative` if it has a box, else its preset from the Canon record, else `none`. v1's Narrative box (no `flags.garn.rect`, at v1's fixed rect) is Garn's: it moves into the padding in the 1.1 look, with the tokens in it.
